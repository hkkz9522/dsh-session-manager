## 0 简介

DSH 会话与工作区管理——工作区：归档与显示。会话：跨工作区移动、预设迁移、删除；收藏、待回看、优先级、标签、备注。批量操作。

Web UI 与 Desktop 共用本插件的 Host 与客户端功能，具体安装方式见下文。

## 1 功能

### 1.1 会话生命周期管理

- **删除**：不可逆操作，UI 始终要求二次确认。删除主会话时会级联清理其后代子智能体会话。
- 删除前取消 Agent 工作，等待其空闲与会话写入收尾；Agent scope 的回收由宿主负责。失败或超时会停止后续删除，并明确报告已完成的部分。
- **投影缓存清理**：删除会话时同时清理其 checkpoint 与旧版聚合缓存条目，覆盖批量删除和级联子智能体删除，并阻止已删生命周期的延迟写回。清理失败会返回警告，不会撤销已完成的会话删除。DSH 根目录可使用 Junction 或符号链接，缓存内部路径的链接仍受限制。
- **归档 / 移出归档**：把会话移出或移回主列表，保留会话历史；关联的 Git 工作树可能按 DSH 设置被清理。
- **移动至工作区**：跨工作区移动时保留历史、标题、归档状态和派生会话关系，同时把 `cwd` 重写为目标工作区，实时同步活动 Agent 的运行时 `workingDirectory` 投影，并就地更新 live writer 的 header，使挂起的工具调用继续落到新路径。若会话的 `cwd` 本来就等于目标工作区、只是归属未登记，则只补全归属记录，不改写 `cwd`、不重写或移动工件、不重启会话。
- **迁移 Agent 预设**：原预设被改名或删除导致会话无法恢复时，可修复该会话。迁移会就地重写最后一条 `agent-preset/selected` 事件（若从未记录则修改会话 header），不改动历史消息。
- 预设候选项准备完成后再显示迁移窗口。准备期间按钮显示忙碌状态，再次点击可取消；准备失败会在面板提示，支持重试。
- 仅允许在会话空闲时切换预设。运行中需先停止任务或等待本轮结束，不会将切换排队到下一轮。
- **Git Worktree**：有关联记录或使用 Git 间接目录的会话会被拒绝跨工作区移动。归档遵循 DSH 的工作树清理设置；删除会话不会删除项目目录、Git 工作树或分支。

### 1.2 会话快捷管理

- **收藏 / 待回看**：长期标记和手动提醒；不会随归档或会话结束自动清除。
- **搜索**：按标题、会话 ID、备注、标签不区分大小写匹配，自动去除首尾空格，不读取聊天历史。
- **筛选与排序**支持叠加工作区（全部 / 未分组 / 具体）、归档状态（全部 / 未归档 / 已归档）、运行状态、收藏、待回看、标签和优先级条件。点击**运行状态**按钮可在不限、运行中和未运行之间循环切换。排序支持最近更新（默认）、最早更新、最新创建、最早创建、名称升序（A → Z）、名称降序（Z → A）和**优先级（1 → 5）**。
- **优先级**：下拉 **1 最高、2 高、3 普通、4 低、5 最低**，**默认 3（普通）**；旧数据中的 `null` 归一化为 3。
- **标签 / 备注**：每会话最多 20 个标签（每个 ≤ 32 字符）、备注最多 2000 字符。英文 `,` 与中文 `，` 都是分隔符，首尾空白被去除，重复标签按大小写不敏感合并。
- **用 AI 整理标记。** 在标记窗口点**复制 Prompt**，粘贴到要整理的对话中。提示词会要求生成便于检索的标签，并用简短备注记录已确认的结果和商定的下一步。将回复的 JSON 粘贴回标记窗口，点**导入**，核对后点**保存标记**。只有在对话中明确指定过优先级时，提示词才要求填写 `priority`；省略该字段会保留当前设置。
- 标记保存在 `dsh-session-manager/annotations.v1.json`，按会话 ID 关联；同源客户端实例通过 `BroadcastChannel` 同步；保存可跨进程崩溃恢复，版本冲突会提示"载入最新内容"。

### 1.3 批量处理

- **批量模式入口**：在会话管理工具栏点击 **批量处理** 切换按钮，行左侧出现复选框，工具栏出现 **全选筛选 / 清空选择** 和 **批量按钮区**；退出批量模式会清空当前选中。
- 一次最多选择 200 个会话，可归档、移出归档、修改标记、移动工作区、迁移预设或删除。**添加标签**会保留已有标签并按大小写不敏感去重。合并超过 20 个标签的会话会列入**失败**，原标签保留。
- 批量删除时，先核对选中的会话和将连带删除的子智能体会话数量。当前这次预览成功后，才能点**确认删除**。
- 宿主处理整批请求时，面板显示等待状态。DSH 逐条执行归档或移出归档时，可点**停止后续操作**。结果按**成功 / 失败 / 跳过**分组，**重试失败项**只处理失败会话；重试删除会重新预览。

### 1.4 插件更新与设置卡片

- **检查更新**：会话管理窗口顶部的 **npm 图标按钮** 可检查新版本并显示小红点提示。一键更新优先使用 DSH 原生更新接口，旧宿主保留回退流程；继续提供安装源保护、镜像源选择、状态持久化、安装后校验和重启/刷新提示，失败时明确显示回滚或人工恢复状态。
- **设置卡片**：注册在 DSH 设置的插件配置页（`settings.plugin.item`）。展示当前安装版本、最新版本状态、卡片内检查更新与更新按钮、自动检查偏好开关以及 GitHub 仓库链接。
- **安装源选择**：在设置卡片中可随时切换安装源，可选 **npm 官方源**（`registry.npmjs.org`，默认）与 **中国大陆镜像源**（`registry.npmmirror.com`）；检查更新与版本下载将直接请求所选源。
- **弹窗透明度**：设置卡片「偏好设置」区域提供 50%–100% 滑块（步长 5%，默认 100%）与「恢复默认」按钮，支持调节插件弹窗的背景填充透明度，文字、按钮、输入框、标签与边框等内容保持不透明并即时生效。
- **主题**：全面跟随 DSH 当前主题（包含第三方主题插件），弹窗、设置卡片、标题栏按钮、下拉菜单、输入框等界面元素自动适配浅色与深色主题。
- **统一下拉样式**：所有下拉选择框（排序、筛选、优先级等）采用跟随主题的无阴影圆角菜单，在可见区域内对齐触发框宽度，并根据空间选择展开方向；缩放、平移或软键盘改变可见区域时自动关闭菜单。

### 1.5 工作区归档与管理

- **双页面切换**：在管理弹窗顶部可在「会话管理」与「工作区管理」之间无缝切换，保留各自的搜索与筛选状态。
- **工作区列表**：完整展示全部已注册工作区，包含工作区名称、物理路径、所属会话数、基于所属会话计算的最近更新时间及状态开关。
- **工作区搜索与筛选**：支持按名称和路径不区分大小写搜索；支持全部 / 未归档 / 已归档筛选；支持按最近更新 / 最早更新 / 名称升序 / 名称降序排序；支持批量归档与取消归档；工具栏按钮自适应折行。
- **显示开关与归档**：
  - **关闭开关（归档）**：执行安全检查（运行中会话拒绝归档），直接将工作区及其所有未归档会话一并归档，并从 DSH 原生侧边栏隐藏。若中途失败，插件会尝试恢复本次已归档的会话。
  - **开启开关（恢复）**：解除工作区归档标记并恢复在原生侧边栏显示，自动恢复此前归档工作区时归档的会话；用户单独归档的会话继续保持归档。新建路径相同的工作区自动恢复显示。
- **原生侧边栏无缝隐藏**：采用派生快照拦截与会话 ID 归属处理，隐藏工作区不会导致其会话错误流入「未分组」，支持深浅主题、持久化存储与 DSH 重启保持。

## 2 UI入口

### 2.1 标题栏入口

标题栏右侧对**当前会话**提供：**归档 / 移出归档**、**收藏**、**待回看**、**标签 / 备注**、**移动至工作区**、**切换预设**、**删除会话**以及**更多操作**（`⋯`），与会话管理面板的操作顺序一致。窄屏下「更多操作」按相同顺序显示全部操作，菜单浮于标题栏容器之外。

### 2.2 会话与工作区管理入口与界面

从 DSH 侧边栏底部进入 **会话与工作区**，可浏览全部会话与工作区。点击会话名称即可打开会话，不再提供独立的「打开」按钮。行操作（含 **迁移预设**）统一使用图标，并提供悬停提示与无障碍名称。会话管理页支持切换工作区、按标题 / ID / 备注 / 标签搜索、筛选与排序；工作区管理页支持搜索、排序、批量处理与显示开关切换。

### 2.3 批量管理入口

管理工具栏的 **批量处理** 按钮即是入口：点一下进入批量模式，行左侧出现复选框，工具栏出现 **全选筛选 / 清空选择** 和 **批量操作** 按钮；再点一次退出批量模式。

### 2.4 设置卡片入口

在 DSH 设置中进入插件设置页（会话管理），可查看版本信息、切换 npm 官方源或中国大陆镜像源、开启/关闭自动检查更新，或手动检查并更新。

## 3 安装

### 3.1 从插件安装

在 DSH 的 **插件** 中添加插件，搜索 `dsh-session-manager` 并安装。该方式适用于官方 Web UI 和 Desktop 客户端。

### 3.2 从第三方插件市场安装

本插件已被 [dsh-market](https://github.com/dsh-market/dsh-market) 和 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) 收录。

### 3.3 通过 CLI 安装至 Web profile

从 npm 安装：

```powershell
dsh plugin --profile web add npm:dsh-session-manager
```

从 GitHub 安装：

```powershell
dsh plugin --profile web add github:hkkz9522/dsh-session-manager
```

安装后重启 DSH Web。若浏览器仍加载旧的客户端代码，可使用 `Ctrl+Shift+R` 强制刷新。

> `desktop` profile 由官方 Desktop 客户端管理，普通 `dsh` CLI 不用于修改该 profile。Desktop 用户请通过客户端内的 **插件** 安装插件。

### 3.4 本地开发 / 测试

#### Web profile

通过 CLI 安装本地仓库：

```powershell
dsh plugin --profile web add <本仓库路径>
```

本地仓库会作为插件 checkout 链接到当前 profile，适合直接修改源码并进行测试。

#### Desktop 客户端

在官方 Desktop 客户端中打开 **插件**，使用本地仓库的绝对路径作为安装源。

对于 Client 端代码，在 HMR 正常工作的情况下，保存修改后可以自动重新加载；若修改未立即生效，可重新加载当前界面或重启对应的 DSH Web / Desktop 客户端。

修改插件依赖、`package.json`、bundle 配置等安装或加载相关内容后，建议重新安装插件或重启对应客户端。

## 4 安全说明

- **删除不可恢复**，UI 始终要求二次确认；删除前校验会话 ID、目录边界和工件 header，不允许通过路径穿越、符号链接或 junction 操作其他目录。
- 移动和迁移预设保留 live session / agent；只有删除才会取消运行并释放会话。移动会更新保存的 cwd 和 live writer 的 header。
- 跨工作区移动前会检查源会话目录。发现备份、旧版日志等额外文件时会停止移动。移动成功后仅移除已经清空的源目录。
- 会话管理列表隐藏 subagent 会话，移动接口也拒绝 subagent；尚未落盘的空白会话不能跨工作区移动。
- 冷会话重写保留原工件格式（V1 / V2 / V3 / V4 都可读，绝不强制升级）。损坏或截断的 Zstd 日志、缺少完整尾行的 JSONL 会拒绝移动 / 重写，不会把部分历史当作完整日志保存。
- 迁移预设按"备份 → 发布 → 回滚"分阶段处理。如果回滚失败，会保留恢复文件并在错误中报告路径；不要删除这些文件。
- 工作区归档回滚或恢复中途失败时，提示会列出仍待恢复的会话 ID，可在工作区管理中点**重试恢复**。若宿主未确认保存，请在同一客户端点**重试保存**，只会重新提交记录。
- 启动时若发现 `cwd` 对应已注册工作区但归属记录遗漏的会话，会通过 DSH 官方接口补全登记（幂等）；扫描不完整时只跳过清理，不会误删现有归属，也不会清除仍在内存中或扫描期间新加入的会话。
- 同一会话的插件写操作按顺序执行；请求体限制为 64 KiB。该队列不替代 DSH 自身的持久化写入协调。
- **集中 API 鉴权**在读取请求体前检查调用者的 owner 权限。新版 WebServer 路由校验宿主传入的已鉴权 peer，旧版双参数路由通过 `connection.admit()` 鉴权。缺少有效凭据或调用者没有 owner 权限时，接口会拒绝请求。

## 6 开发

- `lib/index.js` 是 host 端 ESM 插件，`lib/client.js` 是客户端 UI bundle，无需构建步骤。
- 提交修改前请运行：

```powershell
npm run check
npm test
npm run check:package
git diff --check
```

测试使用隔离临时目录和真实插件入口，不操作真实会话。CI 在 Windows / Linux、Node 22.15.0 / 24 上执行相同检查。

可选集成检查：对正在运行的 DSH Web profile 测试实例执行 `node scripts/smoke-test.mjs`；它会请求实际服务，不属于默认单元测试。

### 永久删除事件

自行保存会话引用的插件可以监听 `session-manager/session-deleted`，并等待自身的变更保存完成。

```js
ctx.on("session-manager/session-deleted", async ({ sessionId }) => {
  await forgetSessionReference(sessionId);
});
```

会话永久删除且移出工作区登记后会发送该事件。它适用于单条、批量和级联删除，子会话先于父会话通知。重复删除可能再次发送同一 ID，监听器应保持幂等。请在监听器中等待自身的持久化，并避免在回调中再次调用会话管理器的写操作。删除请求最多等待每次通知三秒，监听器报错或超时会返回清理警告，删除仍报告成功。超时的监听器仍可在后台完成。
