## 0 Обзор

Диспетчер сессий и рабочих областей DeepSeek Harness — рабочие области: архивация и видимость. Сессии: перемещение, смена пресета, удаление, избранное, отметка «посмотреть позже», приоритеты, теги и заметки. Пакетные операции.

Веб-интерфейс и десктопное приложение используют одну и ту же функциональность хоста и клиента; особенности установки для каждой среды описаны ниже.

## 1 Возможности

### 1.1 Управление жизненным циклом сессий

- **Удаление** необратимо и всегда требует подтверждения. При удалении родительской сессии также удаляются её дочерние сессии субагентов. Сохранённые сессии, включая импортированные разговоры, можно удалять, не открывая их.
- Удаление отменяет работу Agent и ожидает завершения простоя и отложенных записей сессии; хост при этом сам завершает область Agent. Ошибка или тайм-аут останавливает дальнейшее удаление и сообщает о частичном выполнении.
- **Очистка кэша проекций**: при удалении сессии также удаляются её контрольная точка и сохранённая устаревшая запись кэша — в том числе для каскадных субагентов и пакетного удаления. Отложенные записи от удалённого жизненного цикла блокируются. Ошибки очистки выводятся как предупреждения и не отменяют удаление сессии. Настроенный каталог DSH home может быть junction или символической ссылкой; ссылки внутри путей кэша по-прежнему ограничены.
- **Архивация / восстановление** перемещает сессию в активный список и обратно, сохраняя историю разговора. Связанные Git worktrees могут быть очищены в соответствии с настройками DSH.
- **Перемещение в рабочую область** сохраняет историю, заголовок, состояние архива и связи производных сессий, переписывает `cwd` сессии на целевую рабочую область, синхронизирует проекцию `workingDirectory` для активных агентов и обновляет заголовок живого writer на месте, чтобы отложенные вызовы инструментов продолжали писать по новому пути. Если `cwd` сессии уже совпадает с путём целевой рабочей области, но её членство не было зафиксировано, исправляется только отсутствующая запись о членстве: без перезаписи `cwd`, без перезаписи или перемещения артефакта и без перезапуска сессии.
- **Смена пресета агента** перезаписывает последнее событие `agent-preset/selected` (или заголовок сессии, если такого события нет), чтобы сессию с переименованным или удалённым пресетом можно было продолжить. История сообщений никогда не изменяется.
- Диалог пресетов открывается с уже готовым списком вариантов. Кнопка действия показывает подготовку; повторный щелчок отменяет её. Ошибки подготовки отображаются в панели, и их можно повторить.
- Пресет можно сменить только когда сессия простаивает. Остановите задачу или дождитесь завершения текущего хода; изменение не откладывается на следующий ход.
- **Git Worktree**: перемещения между рабочими областями отклоняются, если у сессии есть зафиксированная связь с Worktree или она использует каталог косвенного перенаправления Git (Git indirection directory). Архивация следует настройкам DSH по очистке Worktree. Удаление сессии не удаляет каталоги проекта, Git worktrees или ветки. [Руководство DSH по архивации worktree](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.5/docs/upgrade-guide/v0.2.2-rc.1/archive-worktrees/guide.md)

Одиночные и пакетные перемещения используют дерево рабочих областей. Смена пресета использует выпадающий список.

### 1.2 Быстрые действия с сессиями

- **Избранное / «Посмотреть позже»** — ручные метки, которые сохраняются при архивации и завершении сессии; ни одна из них не сбрасывается автоматически.
- **Поиск** сопоставляет заголовок, ID сессии, заметку и теги без учёта регистра, убирает лишние пробелы и никогда не читает историю чата.
- **Фильтры и сортировка** объединяют рабочую область (Все / Без группы / конкретная), состояние архива (Все / Активные / В архиве), статус выполнения, избранное, «посмотреть позже», теги и приоритет. Кнопка **Статус выполнения** переключает значения: любой, выполняется, не выполняется. Сортировка: по времени обновления (по умолчанию), по времени обновления по возрастанию, по дате создания (сначала новые / сначала старые), по имени (А–Я / Я–А) или по **приоритету (1 → 5)**.
- **Приоритет** — выпадающий список: **1 — высший, 2 — высокий, 3 — обычный, 4 — низкий, 5 — самый низкий**; по умолчанию **3 (обычный)**. Устаревшие значения `null` нормализуются в 3.
- **Теги / заметки**: до 20 тегов на сессию (не более 32 символов каждый) и заметка до 2000 символов. Разделители — как английская запятая `,`, так и китайская `，`; пробелы обрезаются, повторяющиеся теги объединяются без учёта регистра.
- **Помощь модели в создании тегов.** В редакторе заметок выберите **Скопировать промпт** и вставьте его в нужный разговор. Промпт просит модель предложить теги, по которым удобно искать, и краткую заметку с подтверждёнными результатами и согласованным следующим шагом. Приоритет запрашивается только если вы явно его задали. Вставьте ответ JSON в редактор, выберите **Импорт**, проверьте поля и нажмите **Сохранить заметки**. Если поле `priority` отсутствует, текущее значение сохраняется.
- Заметки хранятся обычным текстом в каталоге DSH home (`dsh-session-manager/annotations.v1.json`) и привязаны к ID сессии. Клиентские экземпляры с тем же origin синхронизируются через `BroadcastChannel`. Сохранения переживают сбои; при конфликте версий появляется запрос «загрузить последнюю версию».

### 1.3 Пакетное управление

- **Режим пакетной обработки**: щелкните переключатель на панели инструментов — появятся флажки у строк, пара кнопок **Выбрать все по фильтру / Очистить выбор** и панель пакетных действий. При выходе из режима текущий выбор очищается.
- Можно выбрать до 200 сессий и архивировать или восстановить их, изменить заметки и приоритет, переместить в рабочую область, сменить пресет или удалить. **Добавить теги** объединяет теги без учёта регистра. Если после объединения их количество превысит 20, сессия сохраняет исходные теги и попадает в список **Ошибок**.
- Перед удалением проверьте выбранные сессии и количество дочерних субагентов. Кнопка **Удалить** становится доступной только после успешного предварительного просмотра для текущего выбора.
- Пока хост обрабатывает пакет, панель показывает сообщение ожидания. Когда DSH обрабатывает архивацию или восстановление по одной сессии за раз, оставшиеся операции можно остановить. Результат группирует сессии по разделам **Успешно**, **Ошибки** и **Пропущено**. **Повторить неудачные** действует только на неудачные сессии и заново открывает предварительный просмотр для удаления.

### 1.4 Обновления плагина и настройки

- **Проверка обновлений**: кнопка с значком npm в заголовке панели проверяет наличие обновлений и показывает точку-уведомление при появлении новой версии. Обновление в один щелчок использует штатную операцию DSH, если она доступна, с резервным вариантом для старых хостов. Защита по источнику установки, выбор реестра, сохранение статуса, проверки после установки и запросы на перезапуск / обновление страницы остаются доступными; при ошибках сообщается об откате или о необходимости ручного восстановления.
- **Карточка настроек** регистрируется в настройках DSH (`settings.plugin.item`). В ней отображаются текущая и последняя версии, встроенные кнопки проверки и обновления, переключатель автоматической проверки и ссылка на репозиторий GitHub.
- **Источник установки (реестр)**: в карточке настроек можно выбрать **официальный реестр npm** (`registry.npmjs.org`, по умолчанию) или **зеркало в континентальном Китае** (`registry.npmmirror.com`). Проверка обновлений и загрузка пакетов идут через выбранный реестр.
- **Прозрачность диалогов**: ползунок от 50% до 100% с шагом 5% (по умолчанию 100%) и кнопка «Сбросить по умолчанию» в разделе настроек карточки. Изменяет прозрачность фона диалогов плагина в реальном времени, оставляя текст, кнопки, поля, теги и границы полностью непрозрачными.
- **Тема**: автоматически следует активной теме DSH, включая сторонние плагины тем. Диалоги, карточки настроек, кнопки в строке заголовка, меню, поля и остальные элементы интерфейса плавно адаптируются к светлой и тёмной темам.
- Выпадающие списки фильтров, сортировки и заметок остаются в пределах видимой области окна.

### 1.5 Архивация и управление рабочими областями

- **Переключение между двумя страницами**: в заголовке диалога можно без потери состояния переключаться между «Управлением сессиями» и «Управлением рабочими областями» — у каждой страницы сохраняются свои поиск, фильтры и сортировка.
- **Список рабочих областей**: все зарегистрированные области с названием, физическим путём, количеством сессий, временем последней активности (вычисляется по сессиям-участникам) и переключателем справа.
- **Поиск, фильтры и сортировка**: поиск без учёта регистра по названию и пути; фильтр «Все / Активные / В архиве»; сортировка по времени обновления, по времени обновления по возрастанию, по имени А–Я или Я–А; счётчик и адаптивный перенос панели инструментов.
- **Переключатель и архивация**:
  - **Выключить (архивировать)**: сначала проверяет активность сессий (безопасно безопасно отклоняет операцию, если какая-то сессия выполняется), архивирует все не заархивированные сессии-участники, скрывает рабочую область из родной боковой панели DSH и пытается восстановить сессии, изменённые операцией, если позже возникнет ошибка.
  - **Включить (восстановить)**: снимает метку архива, возвращает область в родную боковую панель, восстанавливает сессии-участники, ранее заархивированные вместе с областью, и сохраняет по отдельности заархивированные сессии. Создание области с тем же путём автоматически восстанавливает видимость.
- **Скрытие из родной боковой панели без «рассыпания» в «Без группы»**: используется перехват производного снимка с объединением ID сессий в `archivedSessionIds`, чтобы скрытые сессии рабочей области не попадали в «Без группы»; поддерживаются светлая и тёмная темы и восстановление состояния после перезапуска DSH.

## 2 Точки входа в интерфейс

### 2.1 Строка заголовка

В правой части заголовка доступны действия для **текущей сессии**: **Архивировать / Восстановить**, **Избранное**, **Посмотреть позже**, **Теги / Заметки**, **Переместить в рабочую область**, **Сменить пресет**, **Удалить сессию** и **Дополнительные действия** (`⋯`) — в том же порядке, что и в панели управления. На узких экранах «Дополнительные действия» показывает те же пункты во всплывающем меню вне строки заголовка.

### 2.2 Вход в управление сессиями и рабочими областями и его интерфейс

В нижней части боковой панели DSH выберите **Сессии и рабочие области**, чтобы просмотреть все сессии и рабочие области. Щёлкните по заголовку сессии, чтобы открыть её; отдельной кнопки «Открыть» нет. Действия в строках, включая **Сменить пресет**, представляют собой значки с описаниями при наведении и доступными подписями. Вкладка сессий поддерживает переключение рабочих областей, поиск по заголовку / ID / заметкам / тегам, фильтрацию и сортировку; вкладка рабочих областей — поиск, сортировку, пакетные действия и переключение видимости.

### 2.3 Пакетное управление

Кнопка **Пакетная обработка** на панели инструментов диспетчера сессий — точка входа: первый щелчок включает режим пакетной обработки (появляются флажки у строк, пара кнопок **Выбрать все по фильтру / Очистить выбор** и панель пакетных действий), повторный — выключает его.

### 2.4 Карточка настроек

Перейдите в настройки DSH → Плагины → Диспетчер сессий, чтобы посмотреть версии, переключаться между официальным реестром npm и зеркалом в континентальном Китае, включать автоматическую проверку обновлений или запускать обновление.

## 3 Установка

### 3.1 Установка через «Плагины»

В DSH откройте раздел **Плагины**, добавьте плагин, найдите `dsh-session-manager` и установите его. Этот способ поддерживается и официальным веб-интерфейсом, и десктопным приложением.

### 3.2 Установка из сторонних маркетов плагинов

Плагин есть в [dsh-market](https://github.com/dsh-market/dsh-market) и [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin).

### 3.3 Установка в профиль Web через CLI

Установка из npm:

```powershell
dsh plugin --profile web add npm:dsh-session-manager
```

Установка из GitHub:

```powershell
dsh plugin --profile web add github:hkkz9522/dsh-session-manager
```

После установки перезапустите DSH Web. Если браузер всё ещё загружает старую клиентскую сборку, выполните принудительное обновление страницы через `Ctrl+Shift+R`.

> Профиль `desktop` управляется официальным десктопным приложением и не предназначен для изменения обычным CLI `dsh`. Пользователям десктопной версии следует устанавливать плагин через раздел **Плагины** в приложении.

### 3.4 Локальная разработка и тестирование

#### Профиль Web

Установите локальный репозиторий через CLI:

```powershell
dsh plugin --profile web add <path-to-this-repository>
```

Локальный репозиторий связывается с текущим профилем как проверка плагина (plugin checkout), поэтому в нём удобно сразу править исходный код и проверять изменения.

#### Десктопное приложение

Откройте **Плагины** в официальном десктопном приложении и укажите абсолютный путь к локальному репозиторию в качестве источника установки.

Для клиентского кода изменения могут подхватываться автоматически после сохранения, если HMR работает нормально. Если изменение не проявилось сразу, перезагрузите текущий интерфейс или перезапустите соответствующий клиент DSH Web / Desktop.

После изменения зависимостей плагина, `package.json`, конфигурации bundle или других параметров установки и загрузки рекомендуется переустановить плагин или перезапустить соответствующий клиент.

## 4 Безопасность и поведение

- **Удаление необратимо**, поэтому интерфейс всегда запрашивает подтверждение. API перед удалением проверяет ID сессии, границы каталога и заголовок артефакта; обход путей, символические ссылки и junction отклоняются.
- Перемещение и смена пресета сохраняют живую сессию / агента; только удаление отменяет и освобождает сессию. Перемещение обновляет сохранённый `cwd` и заголовок уже работающего writer.
- Перемещения сохраняют постоянную блокировку DSH POSIX `session.lock`. В целевом каталоге используется жёсткая ссылка на тот же inode, а старый каталог может остаться только с этой блокировкой. Занятая аренда холодной сессии, другая блокировка в целевом каталоге или неожиданный исходный файл (например, резервная копия) останавливают перемещение.
- Управляющий список скрывает сессии субагентов, а API перемещения отклоняет их. Пустые сессии без сохранённого артефакта переместить нельзя.
- Холодная перезапись сохраняет исходный формат артефакта (форматы V1 / V2 / V3 / V4 все читаются; плагин никогда не навязывает обновление). Перемещения и перезаписи отклоняют повреждённые / обрезанные журналы Zstd или JSONL с неполной последней строкой вместо публикации частичной истории.
- Смена пресета разделяет резервное копирование, публикацию и откат. Если откат не удался, файлы восстановления сохраняются, а их пути включаются в сообщение об ошибке; не удаляйте их.
- Если архивация или восстановление рабочей области прервалось на середине, в управлении рабочими областями перечисляются оставшиеся ID сессий. Выберите **Повторить восстановление**, чтобы продолжить. Если хост не подтвердил сохранение записи, выберите **Повторить сохранение** в том же клиенте, чтобы отправить запись повторно, не повторяя команды для сессий.
- При запуске сессии, у которых `cwd` указывает на зарегистрированную рабочую область, но запись о членстве отсутствует, повторно регистрируются через официальный API DSH (операция идемпотентна). Неполное сканирование лишь пропускает очистку: существующее членство никогда не удаляется, а живые сессии и членства, добавленные во время сканирования, всегда сохраняются.
- Изменения плагина сериализуются для каждой сессии, а тела запросов ограничены 64 KiB. Эта очередь дополняет, а не заменяет собственную координацию сохранения в DSH.
- **Централизованная проверка доступа к API** требует аутентифицированного владельца на каждом маршруте `/session-manager/api/*` ещё до чтения тела запроса. Версии WebServer, предоставляющие route peer, проверяются напрямую. Старые маршруты с двумя аргументами проходят проверку через `connection.admit()`. Плагин отклоняет запросы без учётных данных владельца или с неверными данными.
- **API удаления.** Для одной сессии запросите `GET /delete-preview?sessionId=…` и отправьте `result.previewToken` вместе с ID в `POST /delete`. Для пакета выполните предварительный просмотр через `POST /delete-preview` с массивом `sessionIds`, затем отправьте те же ID в том же порядке и токен в `POST /batch` с `action: "delete"`. Квитанции (receipts) истекают через две минуты. После истечения, перезапуска или изменения области показа снова откройте предварительный просмотр. Хост журналирует время и запрошенные ID при принятии запроса.
- **Доверие в рамках одного origin (same-origin).** Установленные клиентские плагины и другие сценарии, выполняющиеся на странице аутентифицированного владельца, получают тот же доступ к API владельца, включая чтение заметок и перемещения. Такие сценарии также могут запросить предварительный просмотр удаления. Квитанция связывает запросы с просмотром, но не подтверждает щелчок человека и не идентифицирует вызывающий плагин.

## 6 Разработка

- `lib/index.js` — плагин ESM на стороне хоста; `lib/client.js` — клиентская сборка интерфейса. Шаг сборки не требуется.
- Перед отправкой изменений выполните:

```powershell
npm run check
npm test
npm run check:package
git diff --check
```

Тесты используют изолированные временные каталоги и реальную точку входа плагина, но никогда не реальные сессии. CI выполняет эти проверки в Windows / Linux с Node 22.15.0 / 24.

Дополнительная интеграционная проверка: запустите `node scripts/smoke-test.mjs` на работающем тестовом экземпляре DSH Web-profile. Она обращается к реальному сервису и не входит в набор модульных тестов по умолчанию.

### Событие окончательного удаления

Плагины, хранящие ссылки на сессии, могут подписаться на `session-manager/session-deleted` и дождаться сохранения собственных изменений.

```js
ctx.on("session-manager/session-deleted", async ({ sessionId }) => {
  await forgetSessionReference(sessionId);
});
```

Событие следует за окончательным удалением и отсоединением от рабочей области. Оно охватывает одиночное, пакетное и каскадное удаление; дочерние сессии объявляются раньше родительской. Делайте обработчики идемпотентными, поскольку повторное удаление может снова прислать тот же ID. Дожидайтесь собственного сохранения и не вызывайте из обработчика другие изменения Session Manager. Запрос на удаление ждёт до трёх секунд на каждое уведомление. Отклонение или тайм-аут приводит к предупреждению об очистке, но успешный результат удаления сохраняется. Обработчик, ушедший в тайм-аут, может завершиться позже.

История выпусков — в [CHANGELOG.md](CHANGELOG.md).
